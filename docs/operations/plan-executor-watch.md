# 계획 실행기 서버 밖 감시 (1116-01 · 9-2)

서버 전체나 두 프로세스(tradebot-api · tradebot-cron)가 같이 멈추면 서버 안 하트비트 알림이 나지 않습니다.
그래서 GitHub Actions 가 서버 밖에서 공개 `/health` 를 봅니다. 워크플로 파일은 `.github/workflows/plan-executor-watch.yml` 입니다.

## 무엇을 보나
- 15분마다(정각을 피한 7 · 22 · 37 · 52분) `/health` 의 `plan_executor_heartbeat_age_sec`(실행기 마지막 기록으로부터 지난 초)를 읽습니다.
- 응답이 없거나, 숫자가 없거나, 기준(기본 300초)을 넘으면 워크플로가 **실패**합니다. 실패하면 GitHub 가 실패 알림을 보냅니다.
- 이 값에는 계획 · 종목 · 계좌 정보가 없습니다(숫자 하나뿐). 워크플로에 비밀값은 없습니다.

## Actions 변수 (사용자가 넣음)
GitHub 저장소 Settings → Secrets and variables → Actions → **Variables** 탭에 넣습니다(Secrets 가 아님).

| 이름 | 필수 | 값 | 비고 |
|---|---|---|---|
| `PLAN_WATCH_HEALTH_URL` | 예 | 서버 주소(`https://` 로 시작 · 끝 슬래시 없이) | 비어 있으면 워크플로는 아무것도 하지 않고 성공합니다 |
| `PLAN_WATCH_MAX_AGE_SEC` | 아니오 | 숫자(초) | 없으면 300 |

변수는 배포 후 실행기가 한 번 하트비트를 쓴 뒤에 넣는 것이 좋습니다. 기록이 아직 없으면 「숫자가 없음」으로 실패합니다.

## 한계 (알아 둘 것)
- **공개 저장소는 60일 동안 저장소 활동이 없으면 예약 실행이 자동으로 꺼집니다.** 꺼지면 Actions 탭에서 다시 켜야 합니다.
- 예약 실행은 **늦거나 일부 빠질 수 있습니다**(GitHub 부하 때). 15분 간격이라 알림이 최대 15분 + 기준 시간(5분)쯤 늦을 수 있습니다.
- 실패 알림은 GitHub 계정의 알림 설정(이메일 · 앱)에 따라 옵니다. 텔레그램으로 오지 않습니다.

## 실패 알림이 오는지 확인하는 법 (배포 뒤)
1. Actions 탭 → 「Plan executor watch」 → **Run workflow**.
2. 「일부러 실패시켜 GitHub 실패 알림이 오는지 확인」을 켜고 실행합니다.
3. 실행이 빨간색으로 끝나고 GitHub 실패 알림(이메일 또는 앱)이 오면 정상입니다.
4. 입력값을 끄고 다시 실행하면 초록색이어야 합니다(변수가 들어 있고 서버가 정상일 때).
