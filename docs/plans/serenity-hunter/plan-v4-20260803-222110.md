## 2. v4 계획 전문 (구현 대상)

### 2.1 Context

**왜 이 변경**: 기존 `/influencer/serenity` 는 seed 검증 티커 중심이라 SIVE 같은 첫 언급 급등 시나리오 4개 발견 경로 모두 원천 배제. v4 는 UI 이전에 "인플루언서 1인 소스에 알파가 존재하는가"를 데이터로 답하는 검증 페이지를 먼저 만들고, 검증 통과 시에만 발굴 리스트 UI 를 노출하는 **하드 게이트 + 자동 폐기** 아키텍처.

**의도한 결과**:
1. 검증 결과 알파 있음 → 발굴 리스트 노출 · 시드 100만원 투입 판단 근거
2. 검증 결과 알파 없음 → 발굴 리스트 **자동 폐기** (배너 아님 · 리스트 사라짐)
3. 기존 페이지 무영향

### 2.7 하드 게이트 판정식 (Fable 5 3차 (1) 반영)

**위치**: `backend/discovery/serenity/hunter.py::is_gate_open(session)`

**판정식** (모두 AND):
1. `valid_backtest_events >= 50` where `valid` = `price_at_signal IS NOT NULL AND (return_3d IS NOT NULL OR delisting_flag=true)` · **상폐 이벤트 포함** (Fable 5 3차 (1b))
2. `SELECT COUNT(*) FROM serenity_benchmark_prices WHERE symbol='IWM' >= 50` · **영업일 row 수** (Fable 5 3차 (1a) · 수익률 아님)
3. `MAX(computed_at) FROM serenity_backtests >= now - 48h`
4. `health.warn == false` · **stale 방어** (Fable 5 3차 (1c))
5. `is_deprecation_triggered() == false` · **폐기 강제 close** (Fable 5 3차 (2a))

**적용점**:
- `/verification` `hero.gate_open` · 표시
