# A1 · Toss 실주문 매도 상한 면제 · 청산은 봇이 산 수량까지 (1105-03)

- 검수: `docs/plans/biotech/fable-bundles/2026-11-05-1105-03-01.md` (조건부 GO · 막음 1 · 재질의 불필요)
- 앞 일: `a1-kill-switch-sell.md` (1105-02)

## 문제
1. Toss 어댑터의 한 주문 상한(`EXECUTION_MAX_ORDER_AMOUNT` 기본 10만 원)이 매도에도 걸렸다. 평가액이 10만 원을 넘는 보유 종목은 실주문 손절·추적 매도가 `hard-cap-max-order-amount` 로 거부되었다.
2. 매수 금액 추정은 시세 조회가 실패하면 0 이 되어 상한을 그대로 통과했다.
3. 청산 수량은 Toss 계좌의 그 종목 보유 전체였다. 사용자가 같은 국내 종목을 직접 갖고 있으면 봇 청산이 그 주식까지 팔았다. 평가액 10만 원을 넘으면 상한이 막았지만, 그 아래면 지금도 팔았다. ㉯ 승인 때 「남는 안전장치: 보유 수량」 이라고 적은 것은 틀린 전제였다.

## 고침 (서버 0.3.39 · 화면 변경 없음)
1. Toss 어댑터 하드 상한은 **매수에만** 건다. 매도는 면제한다. 1억 원 확인 플래그는 그대로 추정액으로 붙인다.
2. 매수에서 추정액을 못 구하면(지정가가 아니고 시세 조회 실패) `InsufficientBalance("hard-cap-price-unavailable")` 로 거부한다. 매도는 이 이유로 막지 않는다. 지정가 매수는 지정가로 추정하므로 시세가 없어도 된다.
3. 청산 수량 = min(계좌 보유, 봇이 산 수량). 봇이 산 수량(`audit.bot_entry_qty`)은 진입 감사 행으로 정한다:
   - 체결 수량 > 0 → 체결 수량
   - 체결 0 이고 아직 열린 주문(pending · accepted · partial) → 주문 수량 (reconciler 30초 지연 대비)
   - 체결 0 이고 끝난 주문(canceled · rejected · error 등) → 0. 팔지 않고 신호 `reason` 을 `entry_unfilled` 로 적어 청산 대상(`open_positions`)에서 뺀다 (5초마다 다시 시도하지 않음).
   - 감사 행 없음 → floor(지금 한 번에 사는 금액 ÷ 진입가) 로 근사 · WARNING · 텔레그램 「청산 수량 짐작」 신호마다 1회. 진입가도 없으면 팔지 않고 알림.
4. 같은 5초 주기 안에서 같은 종목은 한 번만 청산한다(`manage_positions`). 기준은 `submit_order` 가 결과를 돌려준 경우다(상태가 rejected·error 여도 포함 · 예외로 끝나면 제외). 계좌 보유 반영이 늦으면 두 번째 청산이 사용자 주식을 팔 수 있기 때문이다. 남은 신호는 다음 주기에 청산한다.
5. 모의 어댑터에는 원래 하드 상한이 없다. 「봇이 산 수량까지」 규칙(exit.py)만 같이 적용된다.
6. 문서: `toss_adapter.py` 머리말 · `.env.example` 설명 · `03-toss-openapi-integration.md` 8-3 · `test_toss_adapter.py` 머리말 · `a1-kill-switch-sell.md` 범위 밖.

## 시험
- `test_toss_adapter.py`: 매도 30만 원 통과 · 매수 30만 원 거부 · 시세 없는 매수 거부(Toss 요청 0회) · 시세 없는 매도 통과 · 시세 없는 지정가 매수 통과.
- `test_daily_loss_stop.py`: 직접 산 20주 + 봇 10주 → 청산 10주 · 20주 남음 / 취소된 진입 → 안 팔고 청산 대상에서 빠짐 / 접수(accepted) 진입 → 주문 수량 3주 / 감사 행 없음 → 근사 10주 · 알림 1회 / 같은 종목 신호 둘 → 한 주기 한 번 · 다음 주기에 두 번째.
- 옛 규칙(보유 전체 매도 · 매도에도 상한)으로 되돌리면 새 시험 6개가 실패하는 것을 확인했다.

## 한계 (알고 두는 것)
- 감사 행이 없을 때의 근사는 실제 체결가가 진입가(후보 가격)보다 낮으면 실제 산 수량보다 클 수 있다. 감사 기록 실패는 주문을 막지 않으므로 1025-02 뒤에도 생길 수 있다. 알림으로 알린다.
- 진입이 아직 열린 주문(접수됨)이면 주문 수량까지 판다. 그 사이 계좌 보유가 사용자 주식뿐이면 그 주식이 팔릴 수 있다(reconciler 지연 최대 약 30초). 단 0.3.39 까지 reconciler 는 신호 연결(`EXECUTION_ENABLED`)도 켜져야 돌았다 → 1105-04 ㉦ 에서 실계좌면 늘 돌게 고침.
- 매도 1억 원 플래그: 시세 조회가 실패하면 추정 0 → 플래그 없음 → 1억 원 이상 매도는 Toss 가 거부할 수 있다. 지금 시드(100만 원)에서는 닿지 않는다.
- signal_router 의 유명 투자자 매도 신호(`vip_watch.py`)는 수량을 예산 ÷ 가격으로 정하고 보유와 무관하다. 지금 꺼져 있다. → 1105-04 ㉣ 에서 「신호 연결이 산 순수량까지」 로 고침.
- 청산 후보(`no_position`) 처리는 이전과 같다(계속 다시 확인).
- 일부만 체결된 진입은 체결분만 판다. 청산 뒤에 추가로 체결된 주식은 신호가 닫힌 채 계좌에 남을 수 있다(옛 규칙에서도 같았다 · Fable 1105-03-02 권고 1).
- 봇 수량을 알 수 없는 신호(`bot_qty_unknown` · 진입가 없음)는 5초마다 WARNING 이 찍힌다(알림은 1회). 진입가는 진입 때 늘 채워져 실제로 생기지 않는 경로다(권고 2).
