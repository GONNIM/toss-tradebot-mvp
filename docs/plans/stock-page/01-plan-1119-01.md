## 3. 화면 순서 (위에서 아래)
1. 머리: 이름 · 기호 · 시장 · 토스 링크 (확인된 주소만 「토스에서 주문 화면 열기」, 아니면 「토스에서 검색」).
2. 가격 · 전문가 의견: 로그인 + 바이오 후보면 `QuotePanel` 의 `QuoteDetails` (실시간 · 저장 종가 · 그림 · 의견 · 요약). 비로그인이면 2절의 한 줄. 후보 밖이면 「이 사이트는 이 종목의 가격 자료를 모으지 않습니다」.
3. 왜 올라왔나: 신호마다 이름 · 날짜 · 값 · 뜻 설명 · 자세히 링크.
4. 다가오는 일정: 임상 완료 예정일 · 남은 날 · 「결과 발표일이 아님」. 지난 날짜는 「지난 일정」.
5. 위험 (공개 자료): 계속기업 문구 상태 · 공시 날짜 · 공시 링크.
6. 내 것: 로그인만 (지금과 같음).
7. 출처: 칸마다 자료 날짜와 출처 이름.

## 5. 서버 (`backend/api/routes/stock.py` · 저장 자료만 · 바깥 호출 0)
- `StockOverview` 에 칸 추가: `catalysts`(임상 완료 예정일 목록) · `going_concern`(상태 · 공시 날짜 · 링크 · 「확인 대상 밖」) · `quote_available`(바이오 후보인지 · 화면이 `QuotePanel` 을 열지 정함) · 신호에 `explain`.
- 출처 (Fable 1차 막음 3 반영):
  - 일정: 레이더 CSV 가 아니라 최신 후보 파일 `biotech_candidates_v3_*.csv` 의 `state_note_v50`/`state_note` (`biotech.py`:650-659 `_latest_candidate_notes`) → 같은 파일의 날짜 해석 함수 재사용(696-708).
  - 계속기업: `going_concern.json` 을 회사 번호(CIK)로 찾는다(`biotech.py`:384-391 `_going_concern_for`). 종목 → CIK 는 레이더 행 값. 장부에 행이 없으면 「확인 대상 밖」, 행이 있고 state=not_found 면 「문구 없음」.
  - 후보 여부: `biotech_quotes.candidate_set()` (저장 파일만 읽음 · 바깥 호출 없는지 구현 첫 단계에서 확인).
- 비로그인 분기는 `quote_view` · `live_price` 를 부르지 않는다. 로그인도 종목 API 안에서는 부르지 않고, 화면이 기존 `/api/v1/biotech/quote/{ticker}` 를 따로 부른다(후보 밖은 그 API 가 404 · 네이버 호출 0 · `biotech.py`:1034-1045).
- 잠금 행(`_locked`) 제거 · 국내 스나이퍼 상태 낱말은 관리자만 (`stock.py`:213-223) · 보유 · 판단은 지금처럼 관리자만.
- 칸 하나가 실패하면 그 칸만 null · 로그 1줄 · 응답 200. 캐시 헤더 `private, no-store` · `Vary: Cookie` 유지.
