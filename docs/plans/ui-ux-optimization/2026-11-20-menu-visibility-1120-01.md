## 1. 목표와 지킬 것

1. 화면을 지우지 않는다. 메뉴에서만 빠진다. 주소 · 알림 링크(텔레그램 11곳) · 화면 안 링크로는 그대로 열린다.
2. 설정 메뉴 아래 「메뉴 보이기」 탭에서 화면마다 보임/숨김을 고른다. 바꾸면 휴대폰과 PC 모두 다음 화면 이동부터 바뀐다.
3. 숨겨도 그 화면의 자료 수집 · 예약 작업은 그대로 돈다(㉢ 가).
4. 「제대로 동작하지 않는 기능」은 고치거나, 고칠 수 없으면 까닭을 화면에 밝힌다(4단계).
5. 실주문 · 비상 정지 · 다시 켜기로 가는 길은 숨길 수 없다(잠금): 계획 목록 · 새 계획 · 보유 인수, 내 계좌, 운영 값, 알림, 메뉴 보이기, (4판) 스나이퍼는 단계 3 에서 비상 정지 상황판을 운영 값(/admin/settings)에도 두고 켜기·끄기 한 바퀴를 확인한 뒤 잠금을 풀었다. 잠금 key 는 7개다: `/plans` · `/plans/new` · `/plans/adopt` · `/account` · `/admin/settings` · `/admin/notifications` · `/admin/menu`. 잠금은 서버 응답과 화면 상수 양쪽에서 강제하고, DB 에 숨김 행이 있어도 잠금 화면은 보임으로 응답한다.

## 3. 단계 1 설계

### 3.1 저장
- 새 표 `menu_visibility` (key 문자열 PK · visible bool 기본 true · updated_at). 행이 없으면 보임. 알림 설정 표(`notification_setting`)와 같은 모양.
- key 는 메뉴 탭 주소만이다(지금 GROUPS 의 탭 24개(후보 13 · 계획 3 · 계좌 2 · 기록 2 · 설정 4)와 새 /admin/menu 를 더해 25개 · 예 `/lab/crazy`). 메뉴에 원래 없는 화면(/lab/backtest · /lab/super-signals · /principles/gate-history · /influencer · 종목 상세 등)은 key 가 아니고, 설정 화면에 「원래 메뉴에 없음」으로 읽기만 보이고 「열어 보기」 링크를 둔다. 허용 목록은 서버 상수 `MENU_SCREENS` 하나이고 목록 밖 key 는 400. `MENU_SCREENS` 와 화면 `GROUPS` 탭 목록이 어긋나면 실패하는 시험을 둔다.
- 표가 없거나 읽기 실패면 「모두 보임」으로 응답한다(메뉴가 사라지지 않게).

### 3.2 서버 API
- `GET /api/v1/menu-visibility` — 공개. `{screens:[{key, visible, locked}]}` 만(updated_at 넣지 않음). 라우터 전체 인증을 쓰지 않고 쓰기 3개 길에만 `require_sniper_token` 을 건다. 비로그인 GET 200 · PUT/POST 401 을 시험한다.
- `PUT /api/v1/menu-visibility/{key}` — 관리자(기존 `require_sniper_token` · 알림 설정과 같음). locked 화면은 409.
- `POST /api/v1/menu-visibility/apply-recommended` · `POST .../show-all` — 관리자.
- 권고 숨김 목록(서버 상수 · 메뉴 탭만 · 4판 7개): `/lab`(실험장) · `/influencer/serenity-hunter` · `/vip` · `/logs` · `/lab/moonshot` · `/principles` · `/rulebook` (뒤 5개는 단계 3 합침으로 같은 내용이 받는 화면에 있음 · 숨긴 옛 화면 맨 위에 「같은 내용」 링크). 29~32(백테스트 · Super Signals · 차단 이력 · /influencer)는 원래 메뉴에 없어 바꿀 것이 없다. 35(화약고) · 36(섹터)은 2단계 결과 전까지 보임. 37(밈)은 보임(사용자가 직접 고름). 합침 15곳은 단계 3 에서 합친 뒤 권고 목록에 더한다. 배포 때 코드가 DB 를 바꾸지 않고 사용자가 「권고대로 숨기기」를 누를 때만 바뀐다. 「권고대로 숨기기」는 권고 목록만 숨기고 나머지 화면의 설정은 건드리지 않는다.

### 3.3 화면
- 메뉴(`frontend/components/layout/AppNav.tsx`): 위 API 를 화면 이동(주소 바뀜)마다 다시 읽고, 마지막 값을 브라우저에 잠시 보관해 첫 그림에서 메뉴가 흔들리지 않게 한다. 숨긴 탭을 뺀다. 묶음의 탭이 모두 숨으면 그 묶음도 뺀다. 원래 탭이 없는 묶음(오늘)은 빼지 않는다. 「기록」 묶음은 잠긴 탭이 없어 두 탭을 모두 숨기면 묶음이 빠지는 것이 의도한 동작이다(주소 · 오늘 화면 링크로는 열림). 메뉴는 보관 값으로 먼저 그리고 응답은 뒤에서 반영한다(그림을 막지 않음). 윗줄 묶음 링크와 PC 분류 링크는 고정 주소 대신 그 묶음·분류의 보이는 첫 탭으로 간다. 읽기 실패면 모두 보임. 지금 화면이 숨긴 화면이면 그 탭은 켜진 채 보인다(길 잃지 않게).
- 숨긴 화면 맨 위 한 줄: 「메뉴에서 숨긴 화면입니다 · 설정 › 메뉴 보이기에서 다시 켤 수 있습니다」(layout 에서 공통). 하위 주소는 가장 길게 맞는 탭 key 로 찾는다(지금 activeTab 규칙과 같음 · also 포함).
- 오늘 화면(`/`): 사용자 결정 11/21 「㉣ 가」. 대상은 「오늘 후보」 7개 칸뿐이다(backend/api/routes/today.py 의 칸마다 가리키는 화면이 숨김이면 그 칸을 뺀다). 칸은 화면(page.tsx)에서 뺀다 — 메뉴 값 읽기 실패면 7개 칸이 모두 보인다. 비로그인 잠금 행(로그인 필요)도 숨김이면 빼고 N 에 센다(로그인 여부 상관없이 같은 규칙). 화면 문구는 「로그인 필요」와 「숨길 수 없음」으로 낱말을 나눈다. 시스템 칸 · 「오늘 할 판단」 · 「보유 경보」는 숨기지 않는다. (4판) Crazy · Moonshot 칸은 둘 다 /lab/crazy 를 가리킨다 — /lab/crazy 를 숨기면 두 칸이 함께 빠지고, /lab/moonshot 만 숨기면 Moonshot 칸은 남는다(합친 화면이 /lab/crazy 이므로). 뺀 칸이 있으면 「숨긴 후보 칸 N개 · 설정 › 메뉴 보이기에서 다시 켤 수 있습니다」 줄을 보인다. 시험: 숨김 0개면 줄 없음 · 1개 이상이면 N 이 맞음 · 시스템 칸은 그대로.
- 새 탭 `/admin/menu`(설정 묶음): 메뉴 묶음별 화면 목록 · 스위치 · 「열어 보기」 링크 · 잠긴 화면 표시 · 「권고대로 숨기기」 · 「모두 보이기」. 비로그인이면 읽기만(스위치 잠김 · 「관리자 로그인 뒤 바꿀 수 있습니다」).
- 휴대폰 폭에서 윗줄 「설정」이 잘리는 문제(Aside 관찰)도 이 단계에서 고친다 — 새 탭으로 가는 길이 막히면 안 되므로. 360px · 390px 그림으로 확인한다.

### 3.4 시험
- 서버: MENU_SCREENS 와 GROUPS 일치 시험은 AppNav.tsx 를 읽어 탭 주소를 뽑고, 파일을 못 읽거나 0개면 실패한다 · 기본 보임 · 숨김 저장/복원 · 비로그인 GET 200 · PUT/POST 401 · locked 409 · 잠금 화면에 숨김 행이 있어도 보임 · 목록 밖 key 400 · 표 없을 때 모두 보임 · 권고대로(다른 설정 안 건드림)/모두 보이기 · MENU_SCREENS 와 GROUPS 일치.
- 표 생성: 기존 `init_db` 의 `create_all` 방식(backend/services/db.py:89-95).
- 화면: 메뉴 필터(숨김 탭 빠짐 · 빈 묶음 빠짐 · 오늘 묶음은 어떤 설정에서도 보임 · 지금 화면은 남음 · 읽기 실패 모두 보임) · 묶음 첫 탭 숨김 뒤 묶음 링크 · PC 분류 링크가 보이는 첫 탭으로 감(예 `/watchlist` 숨김 → 「후보」가 `/sniper` · `/journal` 숨김 → 「기록」이 `/logs`) · 다른 창에서 값을 바꾼 뒤 새로 고침 없이 화면을 한 번 옮기면 메뉴가 바뀜(화면 단위 시험 도구가 없어 브라우저 확인 · 주소와 그림을 PR 에 붙임) · tsc · 브라우저(로컬 `BIOTECH_API_ONLY=1 TELEGRAM_BOT_TOKEN=`)로 숨김→메뉴 빠짐→주소 열림→다시 켜기.
- 배포 뒤: 사용자가 화면 하나를 숨기고, Aside 가 로그인 없이 메뉴를 보고 확인(읽기만).
