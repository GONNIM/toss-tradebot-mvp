# 1119-02 종목명과 종목코드 함께 표시 — 기획

- 등록: 2026-11-19 · 사용자 지시: 「한국주식은 종목명(종목코드) 같이 표기 … 미국주식은 종목코드 하단에 종목명(회사명) … 각각만 표시되는 경우 같이 병기」 · 계획 요약 승인 · ㉥ 텔레그램 알림도 같은 규칙 · ㉦ 가: 미국 알림은 「티커 · 회사명」 (11/19)
- Fable 1차(조건부 GO · 막음 4 · 권고 6) 반영판 (2차 질의용)
- 공개 저장소: 실제 종목명 · 코드를 문서 · 시험에 쓰지 않는다 (예시 「테스트전자(000000)」 · TESTA).
- 순서: 1119-01(PR #228) 병합 뒤 시작 (종목 화면 파일 겹침). 단일 배포.

## 1. 표시 규칙
| 시장 | 이름 있음 | 이름 없음 |
|---|---|---|
| 한국 | `테스트전자(000000)` 한 줄 (좁은 칸은 줄바꿈해도 괄호 모양 유지) | `000000 (종목명 확인 안 됨)` |
| 미국 | 티커(굵게) · 아래 줄 회사명(작게) | 티커만 |
- 링크가 있던 곳은 링크 유지 (`/stock/코드`).
- 이미 규칙을 지키는 곳은 바꾸지 않는다 (예: 대장주 분석 패널).

## 2. 공용 부품
- `frontend/components/stock/StockLabel.tsx` 새로: props `code` · `name?` · `market?`(없으면 6자리 숫자면 KR) · `link?` · `layout?`(inline / stacked). 안에서 `StockLink` 재사용.
- `StockLink` 는 그대로 두고 표시는 StockLabel 로 통일.

## 3. 서버 — 응답에 이름이 없는 곳 (약 14곳)
- 한꺼번에 찾기 (Fable 막음 4): `backend/services/stock_names.py` 에 `lookup_kr_names(codes) -> dict` · `lookup_us_names(tickers) -> dict`.
  - 한국 출처 순서는 기존 `lookup_kr_name` 과 같다 (KrxMarketSnapshot → LiveTapeUniverse → PowderKegList → KrxStockMeta). 날짜가 쌓이는 표(KrxMarketSnapshot · PowderKegList)는 「코드별 최신 날짜 한 행」만 읽는다 (코드 수 × 날짜 수를 읽지 않음 · 하위 조회로 코드별 최대 날짜).
  - 아직 못 찾은 코드만 다음 표로 넘긴다. 코드는 500개씩 나눠 IN 조회한다 (SQLite 변수 한도 대비).
  - 미국: TickerUniverse.company_name → MemeUniverse.name (market='US' 행만 · Fable 권고 2).
  - 전체 시간 한도 2초 (기존 TIMEOUT_SEC 와 같음) · 넘으면 그때까지 찾은 이름만 돌려줌. 표 하나가 실패하면 그 표만 건너뛰고 다음 표로.
  - 이름이 빈칸이거나 코드와 같으면 「못 찾음」으로 본다.
  - 서버 안 기억: 코드 → 이름(또는 못 찾음)을 10분 기억 (Fable 권고 1).
  - 같은 결과 시험: 코드 묶음마다 기존 한 건 조회와 같은 이름을 내는지 비교.
- 붙일 응답: 홈 판단 기한 · 보유 경보 · 판단 일지(목록 · 상세 · 모달) · 토스 코드 표 · 스나이퍼 신호 이력 · 화약고 이벤트 · 시장 목록 · 관심 목록 신호 · 밈 결과 표 · 우량주 무효화 이력 · 원칙 게이트 · 본문 · 계획 목록 · 상세 (구현 첫 단계에서 화면 · 서버 · 알림 대조표를 파일:줄로 다시 만든다).
- 응답 모델에 `name: Optional[str]` 추가 · 기존 키는 바꾸지 않음. 1119-01 의 종목 응답 키 고정 시험이 깨지지 않게 한다 (Fable 권고 4 · 종목 응답에는 새 칸 없음).

## 4. 화면 — 약 31곳을 StockLabel 로

## 5. 텔레그램 (㉥ · ㉦ 가)
- 모양:
  - 한국: `alert_text.stock(name, code)` 그대로 「테스트전자(000000)」 · 이름 없으면 기존 「000000 (종목명 확인 안 됨)」.
  - 미국 (㉦ 가): 「TESTA · 회사명」 한 줄 · 회사명은 앞 24자에서 자르고 「…」 · 이름 없으면 티커만. `alert_text` 에 `us_stock(ticker, name)` 하나 추가.
- 제목에는 이름을 넣지 않는다 (제목 40자 · 재발송 간격 판정 열쇠가 제목이라 이름 유무로 열쇠가 바뀌면 같은 알림이 두 번 나감 · `backend/services/notifier.py`:145-149 · 191 · Fable 막음 3). 이름은 본문에만.
- 주문 경로 지연 금지 (Fable 막음 3): `backend/discovery/live_tape/exit.py`:84-113 청산 수량 짐작 알림은 팔 수량을 돌려주기 전에 기다린다 → 알림을 `asyncio.create_task` 로 떼어 보내 매도 계산이 이름 조회를 기다리지 않게 한다. 계획 실행기 `backend/execution/plan/engine.py`:148-156 `_alert` 도 이름은 기억된 값만 쓰고(없으면 코드만) 새 조회를 기다리지 않는다.
- 고칠 곳 (대조표는 구현 첫 단계에서 다시 `grep` · Fable 권고 3):
  - `backend/discovery/live_tape/exit.py`:107-111 (본문 코드만 → 이름(코드))
  - `backend/execution/plan/drafts.py`:303-308 (초안 요약 종목 표기)
  - `backend/execution/plan/engine.py`:148-156 (`_alert` 본문 「계획 번호 N」 다음 줄에 종목 표기)
  - `backend/services/notifier.py`:401 (이름만 → 이름(코드))
  - `backend/services/notifier.py`:337 · 361 (미국 후보 → 「티커 · 회사명」)
- 알림 문장 규칙(명령문 · 신호 낱말 금지)은 그대로. 발동 조건 · 대상 · 간격은 바꾸지 않는다 (Fable 1차: 경보 규칙 변경 아님).

## 6. 실패 · 빈 경우
| 경우 | 동작 |
|---|---|
| 한국 이름 못 찾음 | `000000 (종목명 확인 안 됨)` |
| 미국 이름 못 찾음 | 티커만 |
| 이름 조회 DB 오류 · 잠금 · 시간 초과 | 이름 없이 응답 200 · 로그 1줄 (목록 전체가 실패하지 않음) |
| 시장 정보 없음 | `isKrCode` / `is_kr_code` 로 판별 (영문자가 든 국내 코드 시험 포함) |
| 코드 모양이 아님 | 받은 글자 그대로 · 링크 없음 (StockLink 기존 동작) |
| 목록이 김 (수백 행) | 표마다 IN 조회 1번 · 행마다 조회 금지 |
| 이름에 괄호 · 특수문자 | 그대로 표시 (HTML 이스케이프는 React 기본) |
| 텔레그램 이름 없음 | 한국 `000000 (종목명 확인 안 됨)` · 미국 티커만 |
| 이름이 빈칸이거나 코드와 같음 | 못 찾음으로 처리 |
| 긴 이름 (미국 회사명 최대 200자) | 화면은 한 줄 말줄임 · 알림은 24자에서 자름 |
| 코드가 500개 넘음 | 500개씩 나눠 조회 |
| 일부 표만 실패 | 그 표만 건너뛰고 다음 표 · 로그 1줄 |
| 전체 2초 넘음 | 그때까지 찾은 이름만 · 나머지는 「확인 안 됨」 |
| 이름 유무가 바뀌어 알림 제목이 달라짐 | 제목에 이름을 넣지 않아 생기지 않음 |
| 영문자가 든 국내 코드 | `is_kr_code` / `isKrCode` 로 한국 처리 |
| 주문 경로 알림 | 이름 조회를 기다리지 않음 (떼어 보냄 · 기억된 값만) |

## 7. 시험
- `lookup_kr_names` · `lookup_us_names`: 출처 순서 · 못 찾음 · DB 예외 · 조회 횟수(표마다 1번).
- 붙인 응답마다 `name` 키 · 이름 없음 시험.
- StockLabel 표시 규칙: tsc + 화면 렌더(1280 · 380) 대표 화면 5곳 이상.
- 텔레그램 문장 시험 5곳 · 제목에 이름 없음 · 청산 수량 계산이 이름 조회를 기다리지 않음(느린 가짜 조회로 시험) · 미국 24자 자름.
- 한꺼번에 찾기와 한 건 조회 결과 비교 · 500개 넘는 묶음 · 표 하나 실패 · 2초 한도 · 빈 이름.
- 계획 실행기 시험 묶음(`tests/test_plan_*.py`) · 정해진 시각 잡 시험(`tests/test_job_watch.py`) 통과 (Fable 권고 5).
