## 1. 문제와 원인
- 섹터 점수는 `KrxStockMeta.market_cap_krw` 를 읽는다(analysis.py:149-150 · :199 · 점수 :92 log10(시총)×수출 비중 · 품목 안 순위 :232). 이 표를 갱신하는 `upsert_meta`(krx_price/loader.py:43)를 부르는 코드가 없어 처음 적재한 값 그대로다.
- `last_close` 도 같은 표에서 읽는다: top10.py:222(없으면 후보 제외) · :235(네이버 실패 시 대체 가격).
- 바뀌는 것: 품목 안 순위 · 품목 상위 3 구성(routes/sector_leaders.py:202-209) · 여러 품목 종목의 대표 품목(:359-366, 603-607 · stock.py:207) · 화면 시총. 바뀌지 않는 것: 섹터 백테스트 · Top10 매력도 · 알림 후보 선정(입력에 시총 없음).

## 2. 고침
1. 섹터 잡 3개(1일 11:30 · 11·21일 12:00 · scheduler.py)의 재계산 직전에 `_krx_meta_refresh` 단계를 넣는다. `_krx_candles_refresh` 처럼 받기 전 `session.commit()` · try/except · 실패해도 재계산은 돈다. 새 예약 작업은 없다.
2. 섹터용 받기 함수를 새로 둔다(FDR `StockListing("KOSPI")` + `("KOSDAQ")` · 매핑 51종목만). 기존 `fetch_all_meta` 는 보유 관리(holdings_swing.py:324-327, 361-364)가 쓰므로 바꾸지 않는다(M2).
3. 값 지키기(M1): 유한하고 0 보다 큰 시총 · 종가만 쓰고 아니면 옛 값을 둔다. 받은 목록 행 수가 기준 미만이거나 51종목 중 찾은 수가 기준 미만이면 갱신 전체를 건너뛰고 로그를 남긴다. 기존 `upsert_meta` 의 0 → None 덮어쓰기는 이 경로에서 쓰지 않는다.
4. 출처 고르기(M3): 이번 갱신이 실패하면 「최신 KrxMarketSnapshot」과 「KrxStockMeta」 가운데 날짜가 더 새로운 쪽을 쓴다. 한 번의 재계산에서는 51종목 모두 같은 출처를 쓰고, 그 출처에 빠진 종목만 다른 출처로 채운다. 로그에 종목 · 출처 · 날짜를 남긴다.
5. top10 `last_close` 대체값에 스냅샷 종가를 쓰면 `price_at` 에 스냅샷 날짜를 넣어 낡은 값임이 보이게 한다.
6. 11:30 · 12:00 에 받은 값은 장중 값일 수 있다(추정) — 로그 · 주석에 적는다.
7. `naver_quote/client.py:25` 의 「매일 야간 갱신」 주석을 사실대로 고친다.
8. 화면 시총 기준일 표시는 하지 않는다(M4 · fetched_at 은 onupdate 라 기준일로 못 씀).
