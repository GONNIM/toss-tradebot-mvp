# Toss Tradebot 고도화 작업 지시서 (Claude Code 프롬프트)

너는 이 리포지토리(toss-tradebot-mvp)의 시니어 퀀트 엔지니어다.
아래 지시에 따라 5개 모듈을 고도화하라. 각 Phase는 독립적으로 커밋 가능해야 하며,
Phase 0(공통 인프라)을 먼저 완료한 뒤 나머지를 우선순위 순서대로 진행한다.

**전체 우선순위: Phase 0 → Phase 1(Activist) → Phase 2(스나이퍼) → Phase 3(섹터) → Phase 4(밈주) → Phase 5(VIP) → Phase 6(보안)**

**전역 원칙 (모든 Phase 공통):**
- "절대 실현 손실 0" 철학은 코드/문구에서 전면 제거한다. 대체 원칙: "손실은 작게 자주, 이익은 길게".
- 모든 시그널은 백테스트로 기대값이 검증되기 전까지 `hypothesis` 상태로 표기하고 자동매매에 연결하지 않는다.
- 모든 백테스트는 as-of(발표일/공시일 기준) 정렬, 거래비용(수수료+거래세+슬리피지) 반영, in-sample/out-of-sample 분리를 강제한다.
- 룩어헤드 바이어스가 발생할 수 있는 코드 경로에는 반드시 단위 테스트를 붙인다.

## Phase 0 — 공통 백테스트 인프라 구축 (최우선)

### 목표
모든 모듈이 공유하는 이벤트 스터디 / 전략 백테스트 엔진을 만든다.

### 작업
1. `backend/backtest/` 패키지 신설:
   - `engine.py`: 이벤트 스터디 엔진. 입력 = (이벤트 목록[종목, 이벤트일시, 이벤트타입], 가격 데이터). 출력 = 이벤트 후 t+1일 ~ t+60일 누적초과수익(CAR), 승률, 표본수, t-통계량.
   - `costs.py`: 거래비용 모델. 한국 주식: 위탁수수료(설정값, 기본 0.015%) + 증권거래세(코스닥 0.15%, 코스피는 현행 세율을 설정 파일로 관리) + 슬리피지 모델(호가스프레드 기반, 소형주는 체결가 대비 0.3~1.0% 가정 파라미터화). 미국 주식: 수수료 + SEC fee + 슬리피지.
   - `asof.py`: as-of 데이터 정렬 유틸. 모든 시계열 데이터에 `reference_date`(대상 기간)와 `release_date`(실제 공개 일시)를 분리 저장하고, 백테스트 시 `release_date` 이후에만 사용 가능하도록 강제하는 래퍼. 위반 시 예외 발생.
   - `report.py`: 백테스트 결과를 JSON + HTML 리포트로 출력 (CAR 곡선, 승률, 손익비, MDD, 표본수, 신뢰구간).
2. 벤치마크 대비 초과수익 계산: KOSPI/KOSDAQ 지수 또는 동일 섹터 ETF 대비.
3. 단위 테스트: 룩어헤드 유발 시나리오(release_date 이전 데이터 접근)가 반드시 실패하는 테스트 포함.

### 완료 기준 (Acceptance Criteria)
- [ ] 가짜 이벤트 100건으로 엔진이 CAR 곡선/승률/t-stat을 산출한다.
- [ ] release_date 이전 데이터 접근 시 예외가 발생하는 테스트가 통과한다.
- [ ] 거래비용 파라미터가 config 파일에서 조정 가능하다.

## Phase 1 — Activist Radar 고도화 (우선순위 1)

### AS-IS
SEC 13D/G 5분 폴링, REGIME CHANGE(13G→13D)/CRITICAL/STRONG/WATCH 등급, Wolf Pack 30일 윈도우, DART D001/D002 연동. 참고 신호만 제공, 백테스트 없음.

### TO-BE 작업
1. **이벤트 스터디 백테스트 (핵심)**
   - 과거 13D 필링 데이터(EDGAR full-text search API 또는 저장된 필링 로그)로 최소 3년치 이벤트 수집.
   - Phase 0 엔진으로 이벤트 타입별 CAR 측정: (a) 신규 13D, (b) 13G→13D 전환, (c) Wolf Pack, (d) Tier 1 activist 여부로 층화.
   - 진입 가정: "공시 접수 후 다음 거래 가능 시점의 시가" (공시 순간 가격이 아님 — 개인은 즉시 체결 불가).
   - 2024년 규정 변경(13D 제출기한 10일→5영업일) 전후로 표본을 분리해 드리프트 크기 변화를 비교.
2. **한국(DART) 트랙 분리 검증**
   - 보유목적 '경영권 영향' 신규 보고 이벤트만 추출해 동일 이벤트 스터디. 표본이 100건 미만이면 "표본 부족 — 신호 미검증" 라벨을 UI에 명시.
3. **시그널 → 전략 승격 게이트**
   - 백테스트에서 비용 차감 후 CAR t-stat > 2, 표본 ≥ 100건을 만족하는 이벤트 타입만 `validated` 상태로 승격.
   - `validated` 이벤트에 한해 반자동 주문 티켓(사용자 1클릭 승인) 생성 기능 추가. 완전 자동매매는 붙이지 않는다.
4. **UI 개선**: 각 등급 옆에 백테스트 근거(표본수, 평균 CAR, 승률)를 표시. 근거 없는 등급은 "미검증" 뱃지.

### 완료 기준
- [ ] 이벤트 타입별 CAR 리포트가 생성되고 UI에서 열람 가능하다.
- [ ] 규정 변경 전/후 비교 차트가 존재한다.
- [ ] 미검증 시그널이 자동매매로 연결되는 코드 경로가 없다.

## Phase 2 — 급등주 스나이퍼 고도화 (우선순위 2)

### AS-IS
KOSDAQ Top 30 유니버스, 30초 스캔, tape_score(rank_z/trades_z/book_z), 임계 초과 시 자동 매수, Kill Switch -3%, hard SL/trailing, 10:00~15:00 게이팅, 시드 100만원.

### TO-BE 작업
1. **페이퍼 트레이딩 모드 신설 (실탄 전 필수)**
   - `SNIPER_MODE=paper|live` env 추가. paper 모드에서는 실제 주문 대신 "스캔 시점 최우선매도호가 + 슬리피지 파라미터"로 가상 체결을 기록.
   - 가상 체결 로그 스키마: 진입시각, tape_score, 체결가정가, 청산시각, 청산사유, PnL, 당시 호가스프레드.
   - 최소 200건의 가상 트레이드가 쌓이기 전에는 live 모드 활성화를 코드 레벨에서 차단.
2. **tape_score 임계값 검증**
   - 페이퍼 로그(또는 과거 틱/분봉 데이터가 있다면 리플레이)로 임계값 그리드 서치: threshold × 보유시간 × 트레일링 폭 조합별 승률/손익비/기대값 매트릭스 생성.
3. **9:00~10:00 구간 A/B 테스트**
   - 현재 게이팅이 제외하는 9시대에 대해 페이퍼 모드 병행 스캔을 돌려, 점화 기회의 분포(시간대별 급등 시작 빈도)와 해당 구간 슬리피지를 측정. 데이터로 게이팅 유지/완화 결정.
4. **슬리피지 실측 루프**
   - live 전환 후에는 "주문 시점 예상가 vs 실제 체결가" 차이를 매 건 기록하고, 이 실측 슬리피지를 백테스트 비용 모델에 자동 피드백.
5. **리스크 설계 승격**
   - 스나이퍼의 Kill Switch/hard SL 패턴을 공용 리스크 모듈 `backend/risk/`로 추출: 종목당 포지션 한도(계좌의 N%), 일일 손실 한도, 계좌 MDD 한도. 향후 모든 모듈이 이 모듈을 사용.

### 완료 기준
- [ ] paper 모드에서 가상 체결이 기록되고 대시보드에 표시된다.
- [ ] 200건 미만 시 live 활성화가 차단된다(테스트 포함).
- [ ] threshold 그리드 서치 리포트가 생성된다.

## Phase 3 — 섹터별 주도주 Top 3 재설계 (우선순위 3)

### AS-IS
산업통상부 월간 수출입동향(매월 1일) ↔ KRX 주도주, 17품목 × 24개월 Pearson 상관 + lead/lag 시그널.

### TO-BE 작업
1. **데이터 소스 교체/추가**: 관세청 10일/20일 잠정 수출입 통계 수집 파이프라인 추가. 월간 확정치는 검증용으로 유지.
2. **신호 재정의: 절대치 → 서프라이즈**
   - 각 품목별 수출 증가율의 "예상 대비 괴리"를 신호로 정의. 예상치는 (a) 최근 3개월 추세 외삽, (b) 전년 동월 대비 컨센서스 프록시 중 선택 가능하게 구현.
3. **통계 보강**
   - 상관 분석 기간을 가능한 최장(10년+)으로 확장. 데이터가 없으면 수집부터.
   - 17품목 × 다중 lag 스캔에 다중비교 보정 적용: in-sample에서 발견된 상위 상관 조합만 out-of-sample 홀드아웃 기간(최근 24개월)에서 재검증. 재현 실패 시 폐기.
   - lead/lag 방향 리포트: "주가→수출" vs "수출→주가" 어느 방향이 우세한지 품목별로 명시. 주가가 선행하는 품목은 시그널 소스에서 제외.
4. **as-of 정렬 강제**: 6월 수출 데이터는 7월 1일(잠정치는 6월 11일/21일)부터만 사용 가능하도록 Phase 0의 asof 래퍼 적용.
5. **UI**: 각 품목-종목 페어에 "검증 상태(validated/hypothesis/rejected)" + out-of-sample 성과 표시.

### 완료 기준
- [ ] 잠정치 파이프라인이 동작하고 release_date가 기록된다.
- [ ] lead/lag 방향 리포트가 생성된다.
- [ ] out-of-sample 재검증을 통과 못 한 페어가 UI에서 rejected로 표시된다.

## Phase 4 — 밈주 워치 재정의 (우선순위 4)

### AS-IS
5요소 confluence(공매도·소셜·거래량·모멘텀·촉매) Meme Score, 5분 갱신, Top 10/20/50/100, 미국/한국.

### TO-BE 작업
1. **역할 재정의: 매수 후보 → 과열 탐지 + 관찰 리스트**
   - UI 문구를 "매수 후보 Top N"이 아니라 "과열/주목 종목 모니터"로 변경.
   - Meme Score 점등 후 t+1일~t+20일 수익률 이벤트 스터디(Phase 0 엔진)를 돌려, "점등 시 매수"의 실제 기대값을 측정해 결과를 UI에 그대로 게시(음수여도 게시).
2. **데이터 신선도 라벨링**
   - 각 요소별 데이터의 as-of 시각과 지연을 표시: 예) 미국 공매도 잔고(FINRA) = 격주/약 2주 지연, 한국 공매도 잔고 = 공시 지연 반영. 지연이 큰 요소는 스코어 가중치를 낮추거나 별도 표기.
3. **역방향 활용 실험**
   - "Score 최고점 + 모멘텀 꺾임" 조합의 평균 후속 수익률을 측정해, 과열 종목 추격 금지 필터 또는 (미국 한정, 데이터 가능 시) 평균회귀 관점 신호로 쓸 수 있는지 검증.
4. **소셜 소스 명세화**: 한국/미국 각각 어떤 소스를 어떤 주기로 수집하는지 config와 문서에 명시. 수집 실패 시 해당 요소를 스코어에서 제외하고 UI에 표시(조용한 0점 처리 금지).

### 완료 기준
- [ ] 점등 후 수익률 이벤트 스터디 결과가 UI에 표시된다.
- [ ] 요소별 데이터 지연 라벨이 표시된다.

## Phase 5 — VIP 감시 알림 로직 교체 (우선순위 5)

### AS-IS
실보유 종목 심층 감시, 매수가 기반 알림, Activist 필링 추적.

### TO-BE 작업
1. **매수가 앵커 제거**: 알림 기준을 매수가(cost basis)에서 다음으로 교체:
   - 변동성 기반: ATR(14) 배수 이탈 (예: 종가가 20일 EMA - 2×ATR 하회 시 알림).
   - 구조 기반: 최근 N일 스윙 저점/고점 돌파.
   - 이벤트 기반: 공시(DART/EDGAR), 거래량 z-score 급증, 관련 Activist Radar 이벤트.
2. **손절 규칙 연동**: Phase 2에서 만든 공용 리스크 모듈과 연결해, 보유 종목마다 "진입 시 정한 무효화 가격(invalidation level)"을 필수 입력받고 그 이탈 시 최우선 알림.
3. **매수가는 표시용으로만 유지**: PnL 표시는 유지하되, 알림 트리거 조건에서 cost basis 참조 코드를 제거하고 테스트로 회귀 방지.

### 완료 기준
- [ ] 알림 트리거에 cost basis를 참조하는 코드가 없다(테스트 포함).
- [ ] 종목 등록 시 invalidation level 입력이 필수다.

## Phase 6 — 보안·운영 하드닝 (병행 가능)

### AS-IS
공개 페이지에 내부 설정 절차(로컬 경로, SOPS 파일명, env 변수명) 노출, 공개 페이지에 토큰 입력 UI, localStorage 토큰 저장.

### TO-BE 작업
1. 스나이퍼 설정 가이드(터미널 명령, 로컬 경로 `/Users/...`, env 키 이름)를 공개 페이지에서 제거하고 리포지토리 내부 문서(`docs/ops.md`)로 이동.
2. 관리/실행 계열 엔드포인트(파라미터 편집, 재싱크, 주문): 인증 미들웨어 필수화 + rate limit + 실패 시 지수 백오프 + 감사 로그(누가/언제/무엇을).
3. 토큰: localStorage 대신 httpOnly 쿠키 세션 또는 최소한 만료 시간이 있는 토큰으로 교체. 토큰 회전(rotation) 절차 문서화.
4. 홈 화면 문구 수정: "절대 실현 손실 0" 제거 → "규칙 기반 손실 관리 · 검증된 시그널만 자동화" 로 교체. 목표 문구 "1,000만원 → 1억원"은 "위험 대비 수익(MDD 대비 CAGR) 극대화"로 교체.
5. 공개 페이지 전체에 투자 권유 아님 고지 일관 적용(밈주 워치 수준의 고지를 전 모듈로 확대).

### 완료 기준
- [ ] 공개 페이지 소스에 로컬 경로/내부 명령이 없다.
- [ ] 인증 없는 관리 엔드포인트 호출이 401을 반환한다(테스트 포함).

## 작업 방식 지시

- 각 Phase 시작 전 해당 모듈의 현재 코드를 먼저 읽고, 이 문서의 가정과 실제 구현이 다르면 차이를 보고한 뒤 계획을 조정하라.
- Phase당 하나의 브랜치, 완료 기준 체크리스트를 PR 설명에 포함하라.
- 외부 데이터 소스 추가 시 수집 실패/스키마 변경에 대한 알림과 재시도 로직을 반드시 포함하라.
- 백테스트 결과가 기대와 다르게 나와도(예: CAR이 음수) 결과를 숨기지 말고 UI와 리포트에 그대로 게시하라. 이 프로젝트의 1차 목표는 수익이 아니라 "엣지의 존재 여부를 숫자로 확인"하는 것이다.
